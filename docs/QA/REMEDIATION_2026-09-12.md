# DAIFY — متابعة إصلاحات QA — 2026-09-12

استكمال العمل على الحسابات والصلاحيات وتجربة ما بعد الدخول ضمن M3.
التقرير الأصلي `QA_REVIEW_2026-09-12.md` محفوظ كسجل للحالة السابقة.
التعديلات محلية فوق ملفات عمل سابقة غير ملتزم بها، ولم يحصل نشر إنتاجي.

## النتيجة الوظيفية

- حساب جديد يتحقق من بريده، يدخل، وينشئ مساحة مطعمه وأول فرع ببيانات محفوظة في PostgreSQL.
- الداشبورد يعرض اسم المطعم والفروع والدور الفعلي، مع حالة فارغة واضحة بدل Oliva والأرقام التجريبية.
- قائمة التنقل تتبع الصلاحيات؛ اختيار مساحة العمل يتحقق من العضوية على الخادم.
- صفحة Team تعمل: دعوة ببريد ودور وفروع محددة، قبول بحساب المستلم، تعديل الدور والحالة.
- إيقاف العضو يمنع الوصول في الطلب التالي؛ قائمة الأعضاء لا تعرض للمدير أشخاصًا خارج حدود إدارته.
- تأكيد البريد وإعادة الإرسال والاستعادة والدعوات تستخدم SMTP قابلًا للضبط مع اختبار صندوق محلي.

## خلل إضافي وُجد أثناء التحقق

عند إرسال نموذج الدخول قبل اكتمال تفعيل JavaScript ظهر إرسال HTML افتراضي
بطريقة GET يضع حقول الحساب في عنوان الصفحة. أُضيف `method=post` ومسار action
صريح، مع تعطيل حقول الحساب وزر الإرسال حتى تصبح المعالجة جاهزة. اختبار متصفح
بـJavaScript معطل يثبت عدم وجود حقول حساب أو أزرار إرسال فعالة؛ وفي نسخة الإنتاج
قد تبقى شاشة التحميل دون إظهار النموذج. الاختبار التفاعلي يتحقق من طريقة POST. البيانات المستخدمة
في إعادة الإنتاج حسابات اصطناعية فقط.

هذه **79 حالة اختبار مختلفة**؛ مجموعة الويب نفسها أُعيدت على بيئتَي dev وproduction.
النتيجة لا تعني اكتمال المنصة أو اعتماد تشغيلها إنتاجيًا.

تغطي اختبارات API التحقق من الدور والنطاق، آخر مالك، الجلسات، استهلاك token
المتزامن، وإيقاف الحساب، إضافة إلى SMTP. تغطي رحلة الويب إنشاء الفرع وإعادة
التحميل، الدعوة والقبول، غياب Team/Billing للـViewer، رفض فتح Team مباشرة،
إيقاف العضوية، الموبايل وفشل الخروج.

استخدمت هذه الجولة **PostgreSQL 17 مستقلًا** في عنقود مؤقت على55433، وليس
PGlite. نجح `prisma migrate deploy` ثم أظهر `migrate status` أن ترحيلَي المخطط
مطبقان. الاختبارات على بيانات مؤقتة؛ لم يُستخدم بريد أو حساب أو قاعدة إنتاج.
تم تثبيت PostgreSQL17 عبر Homebrew للتشغيل المحلي دون تفعيل خدمة تلقائية.

أول تشغيل لمجموعة Web على نسخة البناء توقّف أثناء انتظار صورة محسّنة في صفحة
الدخول. الاستجابة HTML كانت200 والواجهة ظهرت، لكن طلب الصورة بقي معلقًا بعد
الانتقال. نجح جلب الصورة مستقلًا وإعادة التشغيل؛ لا تُعد هذه الجولة اختبار ضغط
لمحسّن الصور أو اعتمادًا لأداء الصور في أول طلب. حُفظ سجل المحاولة الأولى أيضًا.
ظهر كذلك سجل Next داخلي `NoFallbackError` عند فحص المسار غير الموجود، مع نجاح
اختبار404؛ يحتاج متابعة إذا تكرر على مسار صالح.

## المتبقي قبل إغلاق M3

1. إعداد مزوّد SMTP فعلي واختبار الاستلام وإجراءات إعادة المحاولة؛ صندوق الاختبار
   المحلي لا يثبت وصول الرسائل إلى البريد الخارجي. الإرسال مباشر بعد commit، دون queue دائمة.
2. تسجيل MFA قابل للاسترداد لمشرف المنصة قبل تفعيل حسابات Admin فعلية.
3. حدود محاولات الدخول خلف وسيط Next: التحقق من فصل العملاء عبر إعداد proxy موثوق.
4. إكمال request/response schemas في OpenAPI؛ المسارات الجديدة موثقة، لكن العقد الكامل ما زال جزئيًا.
5. مراجعة إغلاق M3؛ ثم M4 للمنيو والأقسام والأصناف، وM5 للنشر وروابط QR العامة.

لم تُختبر إدارة نطاق عضو قائم من الواجهة أو قائمة دعوات معلقة/إلغاؤها؛ الواجهة
الحالية تحدد نطاق الدعوة عند الإنشاء وتعدل دور وحالة العضو فقط. لم تُختبر رحلة
تبديل مساحتين بالمتصفح، رغم تحقق endpoint من العضوية. لم تُنفذ MFA recovery أو
عربية كاملة أو اعتماد وصولية شامل أو دفع أو نشر إنتاجي.

## إعادة التشغيل

أنشئ قاعدة اختبار PostgreSQL17 مستقلة باسم `daify_test` واضبط المتغيرين على
رابطها. الاختبارات التكاملية تمسح fixtures في قاعدة الاختبار.

```bash
export DATABASE_URL=postgresql://qa@127.0.0.1:55433/daify_test
export TEST_DATABASE_URL="$DATABASE_URL"
npm run prisma:migrate:deploy --workspace @daify/api
npm run test:api
npm run lint
npm run typecheck
npm run test:web
npm run test:prototype
npm run build
WEB_TEST_PRODUCTION=true npm run test:web
```

للقطات الواجهات مرّر `QA_EVIDENCE_DIR` بمسار مطلق إلى مجلد الأدلة. لا تشغّل
اختبارات API الماسحة أثناء استخدام جلسات Web في القاعدة نفسها. إعداد Mailpit
المضاف في Compose خيار تطوير ولم يُشغّل هنا لغياب Docker؛ اختبار SMTP استخدم
`smtp-server` محليًا داخل الاختبارات.
