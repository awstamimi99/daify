## Implemented behavior

- Immutable numbered versions, source revisions, publisher ids and rollback
  provenance; cross-menu pointer protection and append-only content triggers.
- Revision- and permission-checked design, preview, publish, history, rollback,
  unpublish and QR endpoints, documented in the executable OpenAPI contract.
- Atomic publication/idempotency/audit/outbox transactions and a concurrent,
  idempotent PostgreSQL notification dispatcher.
- Permanent slug reservations, direct canonical redirects, public/unlisted/
  private handling, active-parent checks and no-store HTML/JSON/media responses.
- Retained image references and integrity checks on publish and rollback.
- All nine template defaults/presets and independent Classic/Feast renderers in
  `@daify/menu-engine`; original CSS copied at build time and fonts self-hosted.
- Real dashboard design and publication pages, typed iframe customization,
  responsive/RTL previews, searchable SSR menus and Feast keyboard-accessible
  dish dialogs. The marketing gallery exposes all nine production previews;
  the old Atelier entry point embeds its full production renderer.
- SVG and PNG QR downloads encoding the configured web origin and stable route.

## Local/review setup

1. Install Node 24 dependencies with `npm ci` (builds the shared engine).
2. Configure the API/web example environment files and a disposable PostgreSQL
   database for testing; use explicit `TEST_DATABASE_URL` with a test-named DB.
3. Apply `npm run prisma:migrate:deploy --workspace @daify/api` to the selected
   environment after taking its backup. M5 adds three additive migrations, including conversion of the exact M2 seed theme placeholder.
4. Run `npm run build`, `npm run lint`, `npm run typecheck`, and tests. Production
   browser verification uses `WEB_TEST_PRODUCTION=true npm run test:web`; both
   web and API run their compiled output so generation cannot restart the API.
5. Create a workspace/location/menu, fill required translations and add dishes.
   Open Design or QR & Publish, choose the menu, customize, save and publish.
6. Configure `DAIFY_WEB_ORIGIN=https://daify.net` for real QR downloads; verify
   actual ingress and object storage before customer use.

## Operational handoff

- M6 must connect `publishingEnabled` to authoritative billing entitlements.
  The M5 boolean is an explicit publishing gate, not subscription functionality.
- Public caches are intentionally disabled. Future cache consumers must reconcile
  durable outbox rows after downtime; NOTIFY alone is not reliable offline
  delivery. Define consumer acknowledgement and retention before enabling caches.
- Keep media referenced by any historical version so rollback remains possible.
  Do not run draft-media garbage collection against retained version objects.
- Never recycle old slugs. Printed QR aliases remain owned by their original menu.
- Restore/deployment/S3/SMTP/ingress acceptance from M3/M4 remains open. This local
  result does not close those gates or authorize a production deployment.
- Scheduled publication and custom domains remain explicitly outside M5.
